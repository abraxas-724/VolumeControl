# beta.2 音频启用与面板修复验收

日期：2026-10-05。范围：当前 HyperX Cloud III USB 耳机、BlackHole 2ch 与腾讯会议配置；不代表所有设备/应用覆盖。

## 失败复现与修复

1. 应用音量：旧版在 USB 耳机上报“聚合设备包含额外输入/输出通道”。设备本身只有一个输出流，但其麦克风也进入聚合布局。HAL 使用标志关闭后，回调仍可能提供非空缓冲，旧 DSP 因三个有效通道拒绝启动。新增回归测试先复现；修复后验证布局、关闭无关输入、读回使用标志，并在 C DSP 中固定 tap 缓冲范围，完全不读麦克风数据。
2. 混合路由：用户收到“音频设备或格式发生变化，路由已停止”。系统日志显示 AVAudioEngine 在默认设备切换后重建音频图并把输出从耳机改到 BlackHole。默认引擎改为私有 HAL 聚合设备，真实输出为主时钟，BlackHole 输入启用、BlackHole 输出关闭，缓冲范围固定；不通过忽略通知伪装路由正常。
3. 界面：旧宽度 340、列表仅有最大高度，长能力原因挤占应用行；权限提示隐藏面板时，行的 `onDisappear` 取消启用。改为 480 宽、320 高列表、卡片行、整行滑块、带图标和文字的启用按钮、独立可选择/滚动的错误提示。任务由模型持有，隐藏视图不取消，显式取消/停止/退出才取消。
4. 系统音量：`.onChange` 会把读取刷新当成用户调整写回系统。新增真实 SwiftUI 托管布局测试先复现一次错误写入，再移除反向写入；滑块只在用户操作完成后提交。

所有普通测试使用替身、内存 PCM 和内存设置；界面测试创建离屏 NSHostingView，不访问真实音频设备或改用户偏好。诊断日志、PNG 和 JSON 仅保存在被忽略的 `.build/`。

腾讯会议测试使用 `--verify-target-audio` 原音量转发，不改其保存偏好、不保存声音内容。两进程数字增益与路由结果来自真实 HAL 回调内 PCM；不等同于扬声器声压、端到端延迟或会议听音测量。界面截图使用测试数据，不是用户当前应用状态；GUI 权限提示未自动点击。

显式命令：

```sh
swift test
sh scripts/verify-app-audio.sh
sh scripts/verify-audio-routing.sh
```

路由验收会临时切换默认输出，并在正常结束或失败时恢复。当前固定 HAL 路径要求 BlackHole 与真实输出为相同采样率、相同 1–2 通道 Float32 的单流；不兼容时给出格式原因，不自动改采样率。音频进程、设备或缓冲布局变化仍会停止并提示重新启用。

## 安装、卸载和回滚

- 安装/更新：运行打包脚本并重新打开应用；本地包为 ad-hoc 签名。应用独立音量无需驱动；混合路由需要已安装的 BlackHole 及音频输入权限。
- 授权：首次启用应用音量按 macOS 提示允许系统音频录制。提示出现时可以离开面板，任务继续等待；错误信息不会被刷新覆盖。
- 停止/卸载：停止应用控制及混合路由，确认默认输出为真实设备，再退出并删除应用；权限可在系统设置撤销。更新不会卸载用户已有的 BlackHole。
- 回滚：停止并退出后使用旧包或之前的 tag。beta.1 在带麦克风的 USB 输出上仍有本页所述限制；清理失败先重试停止，不覆盖用户后来选择的输出。

浏览器/其他会议应用、蓝牙与睡眠、Intel / macOS 14.2、长时间性能及正式签名公证继续待验收。
