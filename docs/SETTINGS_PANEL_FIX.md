# 设置入口与面板留白修复

日期：2026-10-06。

## 问题与修改

- 旧设置入口只调用 SwiftUI `SettingsLink`，没有显式激活菜单栏应用或管理窗口置前。真实菜单栏点击未自动复现，但用户报告点击无反应；现改为按钮回调，由主线程 `SettingsWindowController` 创建设置窗口、激活应用并 `makeKeyAndOrderFront`。
- 设置窗口只保留一个实例，关闭时不释放，之后点击重新显示同一个窗口。窗口为 360 × 220 点，不能手动拖成不可用大小；设置 View 不操作 AppKit。
- 新增回归测试首先验证旧设置内容只有 99 点理想高度，低于可用布局阈值，修复后为 220 点。另验证窗口第一次打开、重复打开、关闭后再打开及激活请求。
- 面板上下内边距从各 18 点减到 10 点，并通过 `fixedSize(horizontal: false, vertical: true)` 按内容理想高度布局，避免父窗口的额外高度拉伸内容。测试比较 760 与 1100 点高度约束下的测量结果，面板高度一致；320 点应用列表仍保留。
- 截图中面板背后仍有 Codex 的 `light.png` 静态图片预览；该背景图片不属于软件界面。静态图片上的按钮不能操作应用。

## 验证

- `swift test`：119 项，23 项既有硬件 PoC 跳过，0 失败。
- 最后新增设置背景色后再运行 `swift test --filter SettingsWindowTests`：2 项通过。
- 设置截图与面板截图人工检查通过，截图使用模拟音频/登录项控制，不修改真实系统音量、设备或登录设置。
- Release 构建、ad-hoc 签名检查、`git diff --check` 通过。
- 使用正常退出方式关闭旧实例，再构建并启动本地新版本。

当前进程没有辅助功能权限，自动点击真实状态栏被系统拒绝（osascript 不允许辅助访问）。窗口显示、复用和重新打开已在 AppKit 测试内验证，尚未宣称完成真实菜单栏点击与 VoiceOver 验收。音频设备名称读取错误不在本次修复范围。
